# MacCtrl 1.0.2

发布日期：2026-11-27 · [安装包](#升级) · [校验值](#校验)

修正 1.0.1 中终端标题识别的漏判：FinalShell 里 `Cmd+C` 仍会中断远端进程。

## 修复

1.0.1 已支持按窗口标题识别终端，但只读取"当前活动窗口"自身的标题。实测发现 FinalShell 焦点落在 AWT 子窗口上（标题为空或 `Content window`），真正的标题 `FinalShell 4.6.4` 只存在于顶层窗口，因此仍被判为 GUI。

现在标题与 WM_CLASS 一样沿窗口父链向上最多 16 层查找，任一层命中终端关键字即按终端处理。

实测日志：

```
修复前  命中 cmd-c -> ctrl+c        (mode=Gui)
修复后  命中 cmd-c -> ctrl+shift+c  (mode=Terminal)
```

在 FinalShell 远端执行 `sleep 300` 后按 `Cmd+C`：文本正常复制，`sleep` 未被中断。

## 其他改动

新增 `--verbose` 下的调试日志：每次按键打印焦点判定结果（窗口类、标题、模式），以及命中绑定时的目标组合，便于排查类似的焦点问题。

## 已知限制（未变）

- 仅支持 X11，Wayland 不支持
- `Cmd+Ctrl` / `Cmd+Alt` 组合一律透传
- 跨设备组合键不支持（每块键盘独立状态机）
- 焦点窗口无法确定时按终端处理（fail-safe）
