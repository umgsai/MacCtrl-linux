# MacCtrl 1.0.1

发布日期：2026-11-27 · [安装包](#升级) · [校验值](#校验)

修复 FinalShell 等基于 Java 的 SSH / 终端客户端被误判为普通 GUI 窗口的问题。

## 修复

**问题**：在 FinalShell 里按 `Cmd+C` 会中断远端进程，而不是复制文本。

**原因**：FinalShell 是 Java AWT 应用，窗口 `WM_CLASS` 是通用的 `java-lang-Thread`，不在终端类名白名单里，因此被判定为 GUI 窗口，注入了真实的 `Ctrl+C`。而 `java-lang-Thread` 无法直接加入白名单——IntelliJ IDEA、RustRover 等 IDE 使用同一个窗口类，加入后 IDE 里的 `Cmd+C` 会变成 `Ctrl+Shift+C`。

**解法**：新增窗口标题匹配作为 WM_CLASS 之外的补充判据，窗口类名或标题任一命中即按终端处理。

```toml
[x11]
# 子串匹配、不区分大小写；留空则使用内置默认值 ["finalshell"]
terminal_titles = ["finalshell", "xshell"]
```

默认已内置 `finalshell`，开箱即用。标题读取顺序：`_NET_WM_NAME` → `WM_NAME`。

判定结果不受影响：

| 窗口 | WM_CLASS | 判定 |
|---|---|---|
| FinalShell 4.6.4 | `java-lang-Thread` | 终端（标题命中） |
| MacCtrl-linux – RustRover | `java-lang-Thread` | GUI（标题不命中） |
| deepin-terminal | `deepin-terminal` | 终端（类名命中） |

## 升级

```bash
sudo dpkg -i macctrl_1.0.1-1_amd64.deb
systemctl --user restart macctrl
```

从 1.0.0 升级无需改配置，重启服务即可生效。首次安装请参考 [1.0.0 发布说明](v1.0.0.md) 中的完整步骤（`input` 组、udev 规则、`systemctl --user enable`）。

## 已知限制（未变）

- 仅支持 X11，Wayland 不支持
- `Cmd+Ctrl` / `Cmd+Alt` 组合一律透传
- 跨设备组合键不支持（每块键盘独立状态机）
- 焦点窗口无法确定时按终端处理（fail-safe，宁可透传也不注入 `Ctrl+C`）
