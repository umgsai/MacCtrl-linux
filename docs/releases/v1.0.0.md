# MacCtrl 1.0.0

发布日期：2026-11-27 · [安装包](#安装) · [校验值](#校验) · [已知限制](#已知限制)

MacCtrl 在 Linux（X11）上把 Mac 键盘的 **Command** 键组合映射为 **Ctrl** 键组合。首个稳定版本，功能完整，可日常常驻使用。

## 亮点

- **终端安全**：在终端窗口内 `Cmd+C` 注入 `Ctrl+Shift+C`，不会误杀前台进程；`Cmd+Z` 等无安全替代的组合直接透传原始 Super 组合，终端行为完全不变。
- **所有键盘统一接管**：内置键盘与 USB / 蓝牙外接键盘可同时生效；需要时可按设备名 include / exclude 过滤。
- **延迟转发状态机**：Super 按下后不立即透传，等普通键按下才决定是「注入目标组合」还是「原样透传」，因此未命中的组合没有任何副作用。
- **托盘常驻 + 运行时控制**：托盘菜单提供 暂停/继续、重载配置、列出绑定、打开配置文件、退出；tooltip 实时显示键盘数量与启用绑定数。
- **应用列表入口**：`MacCtrl` 出现在桌面应用列表，点击即通过 `systemctl --user start` 拉起，服务已在运行时不会重复启动。
- **逐项开关**：内置 60 项快捷键目录，35 项默认开启、25 项默认关闭（避免遮蔽桌面快捷键），配置文件可按 id 覆盖，也可用 CLI 临时覆盖。
- **热插拔**：每 2 秒重扫输入设备，插拔键盘无需重启进程。
- **失败即释放**：任一线程注入失败或锁中毒会立即置停主循环并退出进程，内核自动释放全部 evdev grab，不留卡键。

## 环境要求

| 项 | 要求 |
|---|---|
| 显示协议 | 仅 X11（`$XDG_SESSION_TYPE=x11`），不支持 Wayland |
| 权限 | 当前用户在 `input` 组；`/dev/uinput` 可写 |
| 桌面环境 | 不限（依赖 StatusNotifier 托盘；无托盘时自动降级为 headless） |
| 架构 | amd64 |

## 安装

### Debian / deepin / Ubuntu

```bash
# 1) 授予设备权限（一次性）
sudo usermod -aG input "$USER"
sudo udevadm control --reload-rules && sudo udevadm trigger

# 2) 安装
sudo dpkg -i macctrl_1.0.0-1_amd64.deb

# 3) 重新登录后启用用户服务
systemctl --user enable --now macctrl
```

依赖由包自动声明：`libgtk-3-0`、`libayatana-appindicator3-1`、`libgdk-pixbuf-2.0-0`、`libxdo3`、`libx11-6`、`libglib2.0-0`。

### 从源码构建

```bash
sudo apt install -y libgtk-3-dev libayatana-appindicator3-dev libxdo-dev librsvg2-bin
cargo build --release
cargo deb          # 产物在 target/debian/
```

## 升级与迁移（原 cmd2ctrl → MacCtrl）

项目与包名已从 `cmd2ctrl` 更名为 `macctrl`，两者是不同包，**不会自动互相替换**。从 `0.1.0` 升级：

```bash
systemctl --user disable --now cmd2ctrl
sudo dpkg -P cmd2ctrl
sudo dpkg -i macctrl_1.0.0-1_amd64.deb
systemctl --user enable --now macctrl

# 配置不兼容旧路径，需手动搬一次
mkdir -p ~/.config/macctrl && cp ~/.config/cmd2ctrl/config.toml ~/.config/macctrl/ 2>/dev/null
```

## 配置

默认读取 `~/.config/macctrl/config.toml`，不存在则使用内置默认值。

```toml
# 开启默认关闭的 cmd-d
[bindings.cmd-d]
enabled = true

# 禁用默认开启的 cmd-b
[bindings.cmd-b]
enabled = false

# 自定义绑定：keys 为触发组合，gui / terminal 为两种模式下的目标
[bindings.indent]
keys = "shift+]"
gui = "ctrl+shift+]"
terminal = ""          # 空字符串表示在终端里不映射，原样透传

# 追加终端窗口类名（默认已覆盖 17 种常见终端）
[x11]
terminal_classes = ["myterm"]

# 只处理名称包含 Apple 的键盘
[device]
include_patterns = ["Apple"]
exclude_patterns = ["VMware"]
```

命令行可临时覆盖，不写回文件：

```bash
macctrl --enable cmd-d --disable cmd-b
```

## CLI

```
macctrl [OPTIONS]

      --config <PATH>    配置文件路径
      --device <NAME>    只处理名称匹配的键盘（可重复）
      --list-devices     列出事件设备
      --list-bindings    列出快捷键目录及其启用状态
      --enable <ID>      本次运行强制启用绑定（可重复）
      --disable <ID>     本次运行强制关闭绑定（可重复）
      --dry-run          只观察不注入，用于调试
      --no-tray          禁用托盘图标（headless 环境）
      --verbose          输出 debug 日志
  -h, --help             帮助
  -V, --version          版本
```

首次安装建议先跑 `macctrl --dry-run --verbose`，确认能识别键盘、焦点判定的终端/GUI 模式正确后再启用服务。

## 已知限制

- **仅 X11**：Wayland 会话下进程会直接退出。
- **`Cmd+Ctrl` / `Cmd+Alt` 组合不接管**：v1 一律原样透传。
- **跨设备组合键不支持**：每块键盘独立状态机，一块按 Command、另一块按 C 不会触发映射。
- **终端判定的边界**：通过 X11 `_NET_ACTIVE_WINDOW` → `GetInputFocus` 回退 + `WM_CLASS` 匹配识别终端；焦点窗口无法确定时按「终端」安全侧处理，即宁可透传也不注入 `Ctrl+C`。
- **应用列表图标**：在 deepin 等环境下换图标后需 `systemctl --user restart dde-shell@DDE.service` 或注销重登，图标缓存由桌面外壳持有。

## 卸载

```bash
systemctl --user disable --now macctrl
sudo dpkg -P macctrl                 # -P 连同 /etc/macctrl 配置一起删除
rm -rf ~/.config/macctrl             # 可选，删除用户配置
gpasswd -d "$USER" input             # 可选，需重新登录生效
```
